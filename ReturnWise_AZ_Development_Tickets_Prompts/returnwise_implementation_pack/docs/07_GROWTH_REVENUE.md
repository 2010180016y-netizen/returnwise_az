# 07. 초기 유입·시장 검증·수익화

## 검증 가설
H1 사용자에게 반복 반품 경제적 비용 비교의 구체적 불편이 있다. H2 지금 무료 도구보다 명확한 가치가 있다. H3 한 달 수십 건 이상 다루는 사용자는 CSV/이력 관리에 비용을 지불할 것이다. H4 검색 유입은 꾸준한 사용자를 유치할 수 있다.

## 실사용 관찰 (개인정보 최소화)
- 인터뷰 15~20명: 채널, 월간 반품 건수(범주), 현재 계산법, 사용 화면 기록(개인정보 가림), 가장 자주 빠뜨리는 비용, 대안 비교의 정책 제한, 재방문 의사, 월 9900/14900/19900원 가격별 지불 의사/실제 구매 예약 여부.
- MVP 유효 사용자 30명 목표(홍보 실적이 아닌 실제 계산 완료, 응답과 무관한 중복 제거는 사용자의 자발적 참여 기록으로 처리).
- 실사용자가 제공한 계산값은 익명화 후 fixture로 반영하되 주문/고객의 실 정보 저장 금지.

## 콘텐츠 전략 (5개 수동 검수 페이지)
1. 반품 회수비+검수비+회수가치 계산법
2. 환불과 교환의 **비용** 차이 및 권리 문제
3. 환불 시 플랫폼 수수료 환급은 왜 확인이 필요한가
4. 반품 회수가치(재판매 순가치) 계산 방법
5. 무료 반품 처리 체크리스트
자료 기반, 독창적 수식/예시 포함, 대량 AI 생성 글 금지. 검색량/난이도는 발행 전 키워드 확인하고 증거 출처 저장.

## 수익화 순서
1. 무료 실사용 검증.
2. 작업량 높은 반복 이용자를 대상으로 Pro 기능 우선순위·가격 실험(실 결제 없는 의향 조사임을 명시).
3. 실제 지불 확약/구매 의향 확인 후 PG/법률/개인정보/운영비 조사.
4. Pro 유료 시험, 보안·결제 테스트 완료 후 공개.
5. 유료 전환이 검증되지 않으면 관련 B2B 물류/솔루션 제휴 리드 **표시·동의·광고 고지**를 조건으로 테스트.

## 이벤트 지표와 계측 주의
Cloudflare Web Analytics는 페이지뷰·성능 측정에는 적합하지만 공식 문서상 custom events는 지원하지 않음(2026-11-03 조회). 따라서 '계산 시작·완료/버튼 클릭' 계측을 WA만으로 가능하다고 주장하지 말 것. 초기에는 인터뷰/수동 대시보드로 확인. 이후 필요 시 개인정보 검토 후 별도 최소 이벤트 수집안을 ADR로 승인.

## 경제성 지표
월 반복매출(MRR), 신규 유료 고객, 해지율, 유료 고객의 유지기간, 세전 기여이익, CAC, 결제비, 지원비, 부정/환불 비용. 인건비/세금 제외 매출을 순이익으로 표기 금지.

## go / no-go
90일 후 유료의향/실재 고객반응이 미약하면 feature를 늘리기보다 피봇. 수익 모델을 확정하지 못한 것은 실패가 아니라 가설 기각으로 기록.
