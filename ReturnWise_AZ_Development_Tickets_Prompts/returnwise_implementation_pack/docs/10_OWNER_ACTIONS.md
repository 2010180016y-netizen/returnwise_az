# 10. 운영자 직접 실행·승인 체크리스트

개발 에이전트가 독단으로 진행할 수 없는 작업이다. 계정이 없거나 권한이 없다면 구현 완료와 배포 가능을 구분한다.

## 처음 시작할 때
- [ ] 프로젝트 이름/서비스 상표를 실제 검색해 중복 가능성 확인하고 가칭 유지 또는 변경.
- [ ] GitHub private 저장소 생성/선택, 로컬 개발 에이전트 접근 권한 부여.
- [ ] Cloudflare 계정 사용 여부 및 무료 플랜 이용 조건 확인.
- [ ] 도메인 구매 여부 결정. 무료 Pages 서브도메인으로 시작 가능.
- [ ] 공개 사이트 운영자 정보와 연락 가능한 이메일 준비. 실제 정보가 없으면 허구로 생성 금지.
- [ ] 국내 전자상거래법·반품 정책 관련 고지사항을 한국 법률전문가 또는 적절한 검토 체계로 확인.

## 무료 MVP 공개 전
- [ ] 사용자 3~5명에게 공개 전 실사용 피드백 받기.
- [ ] 게시할 개인정보 안내/약관/면책 문구/사업자 정보/제휴 공시 필요 여부 확인.
- [ ] 프로덕션 배포·도메인 연결·Search Console 등록 개별 승인.
- [ ] 소프트웨어에 실제 개인정보 수집/결제 기능이 없는지 검증.
- [ ] 검색봇 허용과 공개 URL 승인.

## Pro 확장 전에만
- [ ] G5 실사용/지불의향 데이터 검증 후 추가 예산 승인.
- [ ] 국내/해외 PG 실제 요금과 사업자 심사 확인, 실명 계약/정산 계좌/세금 이슈 해결.
- [ ] 데이터 보관·삭제/개인정보처리방침 및 정보보호 의무 검토.
- [ ] 명확한 환불 정책 및 지원 가능 시간 설정.
- [ ] 베타 대상 고객과 결제 테스트/실제 과금의 차이를 명확히 설명.

## 운영자 환경이 없을 때 대체 진행
- 프로덕션 작업은 `BLOCKED`; 로컬 build, 자동 테스트, GitHub Actions YAML 초안, 수동 설정 스크린샷 없이도 확인할 수 있는 체크리스트까지 완료.
- 없는 계정/권한을 가진 것처럼 가정하지 않는다.
