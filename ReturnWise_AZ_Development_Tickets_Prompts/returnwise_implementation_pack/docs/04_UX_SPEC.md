# 04. 화면·동선·문구 사양

## 핵심 원칙
단일 페이지, 한국어 우선, 로그인 없음, 핵심 행동 1개. 320px부터 데스크톱까지 수평 스크롤 금지. 무엇을 입력하고 왜 결과가 다른지 30초 내 이해할 수 있게 설명.

## 레이아웃 (위에서 아래로)
1. Header: ReturnWise · 사용방법 · FAQ · 정책/법률 고지.
2. Hero: `반품 한 건, 실제로 얼마가 더 들까요?` + `무료 · 가입 없음 · 브라우저에서 계산`.
3. STEP1: 고객 요청과 반품 사유(모르면 '확인 필요'), 판매 플랫폼, 법령/정책 확인 상태.
4. STEP2: 환급 예정 금액, 회수 운송비(판매자 부담분), 검수/재포장비, 순회수가치, 기타비, 수수료 환급 확정액.
5. STEP3: 대안 선택(전액 환불+회수 / 회수 없는 전액 환불 / 조건부 부분 환불 / 조건부 교환).
6. Result: 비교표와 바 시각화. **현금지출과 순경제적 비용 두 열**. 선택 불가 대안은 회색 `확인 필요`.
7. Breakdown: 대안별 산식 열람, 변수 설명, 누락 비용 경고, 계산 방법 표기.
8. Actions: 결과 복사, 예시 사용, 모두 초기화, 내 기본비용 기억하기(동의 필요).
9. FAQ: 판매가와 회수가치 차이; 단순변심/하자 차이; 수수료환급 불확실; 개인정보 저장 여부.
10. Footer: 운영자 표시(실제 확인된 내용만), 개인정보/서비스 안내, 법률 문서 URL.

## UI 상태
- Empty: 중요 입력칸 비어있음, 결과 없음, 차단 이유.
- Valid: 계산 가능하지만 정책 확인 미완료, 비용만 표시(추천 없음).
- Eligible: 정책·고객 동의 확인된 선택지만 순경제적 비용 오름차순 비교.
- Invalid: 숫자 오입력(음수, 문자, 초과 금액), 필드별 오류 메시지, `aria-describedby` 연결.
- Stale: 저장 schemaVersion 변경 시 구형 기본값 마이그레이션/안전 초기화.

## 문구 가드레일
금지: `법적으로 완벽`, `반드시 부분 환불`, `절대 손해 안 봄`, `확정 수익`, `100% 자동 보장`.
권장: `입력 조건에 따른 추정 비용`, `판매자 부담 운송비`, `실제 회수 가능한 순가치`, `허용된 처리방법만 비교`, `규정 확인 필요`.

## 접근성
semantic heading 순서, 모든 폼에 label, 키보드 탭 순서, focus visible, 44px 터치 타깃 권고, screen reader 오류 안내, `aria-live=polite` 결과 업데이트, 콘트라스트 WCAG 2.2 AA 목표, reduce-motion 존중, 차트는 반드시 수치 표 병행.

## 상호작용
- 결과 복사는 브라우저 Clipboard API, 실패 시 수동 복사 가능한 영역 제공.
- URL 쿼리·해시·analytics payload에 계산 값 및 사용자 입력 삽입 금지.
- 자동 로컬 저장은 가격이 아니라 비민감 '기본 처리비용'만, 사용자가 체크했을 때.
