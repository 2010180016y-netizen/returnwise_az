# T08 | 옵션 자격/정책 확인 게이트

> G1 / 무료 MVP 또는 사업검증 단계
> 선행 조건: T07,T02

## 개발 에이전트에게 붙여넣을 실행 프롬프트

너는 ReturnWise 프로젝트의 구현 책임자다. 먼저 저장소 상태와 `prompts/00_MASTER_PROMPT.md`, `START_HERE.md`, PRD/금융 산식/법률 게이트/기술 명세를 읽고 현재 티켓의 선행 조건 `T07,T02` 완료 여부를 **실제 파일과 테스트로** 확인하라. 선행 조건 미충족이면 임의 보완·월권하지 말고 BLOCKED 보고서를 작성하라.

**현재 실행할 티켓은 T08 — 옵션 자격/정책 확인 게이트 하나뿐이다.**

**목적:** 미확인/비허용 처리안이 최적안으로 오표시되는 것을 방지한다.

**구체적 작업 지시:** eligibility 함수는 eligible/requires_review/ineligible 및 reasons 배열 출력; 고객 요청·정책 검토·합의·특례품목 필드; 부분환불 3요건; 교환 적법 선택 확인; 미확인 플랫폼/귀책은 기본 추천 중지; 전체 cost 결과와 자격 상태 분리.

**최소 산출물:** src/domain/eligibility.ts, tests/unit/eligibility.test.ts. 반드시 구현 및 테스트의 변경 파일 경로를 명시하고 `docs/implementation/T08_REPORT.md`를 남겨라.

**합격 판정기준:** L01–L08 통과; `requires_review`와 `ineligible`을 추천 집합에서 완전 제거; 설명 가능한 차단 이유.

**특별 안전조건:** 상황별 법률 가능 여부를 코드가 자체 확정하는 구조 금지.

실행 순서는 (1) 현 상태 확인 및 작은 실행계획 (2) 최소 변경 구현 (3) 명시한 판정기준의 테스트 작성·실행 (4) 반례·엣지케이스 검토 (5) 변경 파일/테스트 증빙 정리 (6) `PASS/CONDITIONAL/FAIL/BLOCKED` 판정이다. 실행하지 못한 명령은 `NOT_RUN`으로 남기고, 무단 결제/외부 공개/배포/원격 푸시 없이 종료하라. 범위 밖 발견사항은 다음 티켓 후보로 적어라.

**답변 형식:** `판정 → 실제 변경 파일 → 구현 핵심 → 실행한 테스트(명령·결과) → 미검증·잔여 위험 → 다음 티켓 진행 가능 여부`.
