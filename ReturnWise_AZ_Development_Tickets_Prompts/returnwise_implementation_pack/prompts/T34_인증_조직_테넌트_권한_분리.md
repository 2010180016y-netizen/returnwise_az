# T34 | 인증·조직·테넌트 권한 분리

> G6 / **조건부 실행: T32의 G5 PASS와 사용자 별도 승인 후에만 실시.**
> 선행 조건: T33

## 개발 에이전트에게 붙여넣을 실행 프롬프트

너는 ReturnWise 프로젝트의 구현 책임자다. 먼저 저장소 상태와 `prompts/00_MASTER_PROMPT.md`, `START_HERE.md`, PRD/금융 산식/법률 게이트/기술 명세를 읽고 현재 티켓의 선행 조건 `T33` 완료 여부를 **실제 파일과 테스트로** 확인하라. 선행 조건 미충족이면 임의 보완·월권하지 말고 BLOCKED 보고서를 작성하라.

**현재 실행할 티켓은 T34 — 인증·조직·테넌트 권한 분리 하나뿐이다.**

**목적:** 유료 판매자 데이터를 타 계정과 철저히 격리한다.

**구체적 작업 지시:** 검증된 Auth 도구 선택; 조직과 멤버 역할, 서버측 session 검증, 모든 리소스의 orgId 필터, 소유권/권한 테스트, 휴면/삭제/로그아웃; 인증정보/비밀번호 자체 구현 최소화; PII 최소 수집.

**최소 산출물:** server/auth/*, db/migrations/*, tests/security/tenant.*. 반드시 구현 및 테스트의 변경 파일 경로를 명시하고 `docs/implementation/T34_REPORT.md`를 남겨라.

**합격 판정기준:** 다른 조직 데이터 CRUD 403/404; 관리자 UI 우회도 서버 차단; 로그 내 토큰 0건.

**특별 안전조건:** 서버 검증 없이 UI 숨김으로만 접근 통제 금지.

실행 순서는 (1) 현 상태 확인 및 작은 실행계획 (2) 최소 변경 구현 (3) 명시한 판정기준의 테스트 작성·실행 (4) 반례·엣지케이스 검토 (5) 변경 파일/테스트 증빙 정리 (6) `PASS/CONDITIONAL/FAIL/BLOCKED` 판정이다. 실행하지 못한 명령은 `NOT_RUN`으로 남기고, 무단 결제/외부 공개/배포/원격 푸시 없이 종료하라. 범위 밖 발견사항은 다음 티켓 후보로 적어라.

**답변 형식:** `판정 → 실제 변경 파일 → 구현 핵심 → 실행한 테스트(명령·결과) → 미검증·잔여 위험 → 다음 티켓 진행 가능 여부`.
