# T40 | Pro 출시 승인·비용/유지율 관찰

> G6 / **조건부 실행: T32의 G5 PASS와 사용자 별도 승인 후에만 실시.**
> 선행 조건: T39

## 개발 에이전트에게 붙여넣을 실행 프롬프트

너는 ReturnWise 프로젝트의 구현 책임자다. 먼저 저장소 상태와 `prompts/00_MASTER_PROMPT.md`, `START_HERE.md`, PRD/금융 산식/법률 게이트/기술 명세를 읽고 현재 티켓의 선행 조건 `T39` 완료 여부를 **실제 파일과 테스트로** 확인하라. 선행 조건 미충족이면 임의 보완·월권하지 말고 BLOCKED 보고서를 작성하라.

**현재 실행할 티켓은 T40 — Pro 출시 승인·비용/유지율 관찰 하나뿐이다.**

**목적:** 수익을 내는 기능이 운영상 감당 가능함을 확인한다.

**구체적 작업 지시:** 법률·보안·결제/개인정보 독립 리뷰, 결제 실패/환불/이용권 리컨실리에이션, DR/이탈/지원비·MRR 코호트 대시보드, 제한적 베타, 장애/악용/고객 지원, 프로덕션 전 최종 수동 승인; 30일 개선실험 설계.

**최소 산출물:** docs/PRO_LAUNCH_REPORT.md, docs/PRO_OPS_SCORECARD.md. 반드시 구현 및 테스트의 변경 파일 경로를 명시하고 `docs/implementation/T40_REPORT.md`를 남겨라.

**합격 판정기준:** 실제 유료 사용자 데이터/매출 없으면 예상치 명시, P0 결함 0, 보안 게이트 PASS, 명시 승인 후만 Pro 공개.

**특별 안전조건:** 수익 자동 발생·운영 무인화 보장 표현 금지.

실행 순서는 (1) 현 상태 확인 및 작은 실행계획 (2) 최소 변경 구현 (3) 명시한 판정기준의 테스트 작성·실행 (4) 반례·엣지케이스 검토 (5) 변경 파일/테스트 증빙 정리 (6) `PASS/CONDITIONAL/FAIL/BLOCKED` 판정이다. 실행하지 못한 명령은 `NOT_RUN`으로 남기고, 무단 결제/외부 공개/배포/원격 푸시 없이 종료하라. 범위 밖 발견사항은 다음 티켓 후보로 적어라.

**답변 형식:** `판정 → 실제 변경 파일 → 구현 핵심 → 실행한 테스트(명령·결과) → 미검증·잔여 위험 → 다음 티켓 진행 가능 여부`.
