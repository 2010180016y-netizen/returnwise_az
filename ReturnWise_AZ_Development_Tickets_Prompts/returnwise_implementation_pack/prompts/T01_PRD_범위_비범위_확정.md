# T01 | PRD 범위·비범위 확정

> G0 / 무료 MVP 또는 사업검증 단계
> 선행 조건: T00

## 개발 에이전트에게 붙여넣을 실행 프롬프트

너는 ReturnWise 프로젝트의 구현 책임자다. 먼저 저장소 상태와 `prompts/00_MASTER_PROMPT.md`, `START_HERE.md`, PRD/금융 산식/법률 게이트/기술 명세를 읽고 현재 티켓의 선행 조건 `T00` 완료 여부를 **실제 파일과 테스트로** 확인하라. 선행 조건 미충족이면 임의 보완·월권하지 말고 BLOCKED 보고서를 작성하라.

**현재 실행할 티켓은 T01 — PRD 범위·비범위 확정 하나뿐이다.**

**목적:** 무료 MVP와 Pro를 논리적으로 분리한다.

**구체적 작업 지시:** 01_PRD 기반 사용자·JTBD·MVP 기능·비범위·KPI·실패기준을 문서화; 1페이지 사용자 동선과 사전 합의되지 않은 미래 기능 목록 기록; 요구사항을 수용기준 및 ID로 연결; 결정 불가사항은 가정/리스크로 표시.

**최소 산출물:** docs/PRODUCT_SCOPE_LOCK.md, docs/TRACEABILITY_MATRIX.md. 반드시 구현 및 테스트의 변경 파일 경로를 명시하고 `docs/implementation/T01_REPORT.md`를 남겨라.

**합격 판정기준:** 모든 P0 요구사항에 하나 이상의 티켓과 테스트 ID 매핑; Pro 기능은 G5 전 구현 작업 금지.

**특별 안전조건:** 업무 범위를 임의로 확대하지 말 것.

실행 순서는 (1) 현 상태 확인 및 작은 실행계획 (2) 최소 변경 구현 (3) 명시한 판정기준의 테스트 작성·실행 (4) 반례·엣지케이스 검토 (5) 변경 파일/테스트 증빙 정리 (6) `PASS/CONDITIONAL/FAIL/BLOCKED` 판정이다. 실행하지 못한 명령은 `NOT_RUN`으로 남기고, 무단 결제/외부 공개/배포/원격 푸시 없이 종료하라. 범위 밖 발견사항은 다음 티켓 후보로 적어라.

**답변 형식:** `판정 → 실제 변경 파일 → 구현 핵심 → 실행한 테스트(명령·결과) → 미검증·잔여 위험 → 다음 티켓 진행 가능 여부`.
