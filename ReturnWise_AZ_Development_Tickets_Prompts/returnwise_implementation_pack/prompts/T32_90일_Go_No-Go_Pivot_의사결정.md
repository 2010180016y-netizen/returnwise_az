# T32 | 90일 Go/No-Go/Pivot 의사결정

> G5 / 무료 MVP 또는 사업검증 단계
> 선행 조건: T29,T30,T31

## 개발 에이전트에게 붙여넣을 실행 프롬프트

너는 ReturnWise 프로젝트의 구현 책임자다. 먼저 저장소 상태와 `prompts/00_MASTER_PROMPT.md`, `START_HERE.md`, PRD/금융 산식/법률 게이트/기술 명세를 읽고 현재 티켓의 선행 조건 `T29,T30,T31` 완료 여부를 **실제 파일과 테스트로** 확인하라. 선행 조건 미충족이면 임의 보완·월권하지 말고 BLOCKED 보고서를 작성하라.

**현재 실행할 티켓은 T32 — 90일 Go/No-Go/Pivot 의사결정 하나뿐이다.**

**목적:** 낮은 비용으로 사업 가설을 객관적으로 판정한다.

**구체적 작업 지시:** 유효 이용자·반복 활용 사례·지불 의사·유입비용·안전 사고/운영비를 표로 정리; G5 합격 여부 및 유지/개선/피봇 중 선택; 불확실성을 기록; Pro 개발을 위한 P0 리스크 재평가.

**최소 산출물:** docs/GO_NO_GO_90D.md. 반드시 구현 및 테스트의 변경 파일 경로를 명시하고 `docs/implementation/T32_REPORT.md`를 남겨라.

**합격 판정기준:** 실 사용자 지표 근거와 완료/미완료 명확; G5 FAIL이면 T33~40 중지; 결재자 명시 승인.

**특별 안전조건:** 성과 없을 때 낙관적 서사로 개발 계속하지 말 것.

실행 순서는 (1) 현 상태 확인 및 작은 실행계획 (2) 최소 변경 구현 (3) 명시한 판정기준의 테스트 작성·실행 (4) 반례·엣지케이스 검토 (5) 변경 파일/테스트 증빙 정리 (6) `PASS/CONDITIONAL/FAIL/BLOCKED` 판정이다. 실행하지 못한 명령은 `NOT_RUN`으로 남기고, 무단 결제/외부 공개/배포/원격 푸시 없이 종료하라. 범위 밖 발견사항은 다음 티켓 후보로 적어라.

**답변 형식:** `판정 → 실제 변경 파일 → 구현 핵심 → 실행한 테스트(명령·결과) → 미검증·잔여 위험 → 다음 티켓 진행 가능 여부`.
