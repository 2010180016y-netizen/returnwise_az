# T39 | 결제 웹훅·구독상태와 보안 검증

> G6 / **조건부 실행: T32의 G5 PASS와 사용자 별도 승인 후에만 실시.**
> 선행 조건: T34,T37,T38

## 개발 에이전트에게 붙여넣을 실행 프롬프트

너는 ReturnWise 프로젝트의 구현 책임자다. 먼저 저장소 상태와 `prompts/00_MASTER_PROMPT.md`, `START_HERE.md`, PRD/금융 산식/법률 게이트/기술 명세를 읽고 현재 티켓의 선행 조건 `T34,T37,T38` 완료 여부를 **실제 파일과 테스트로** 확인하라. 선행 조건 미충족이면 임의 보완·월권하지 말고 BLOCKED 보고서를 작성하라.

**현재 실행할 티켓은 T39 — 결제 웹훅·구독상태와 보안 검증 하나뿐이다.**

**목적:** 유료 상태를 결제 증빙과 일치시키고 중복처리/무단 접근을 막는다.

**구체적 작업 지시:** PG sandbox API에 한하여 서버 검증, webhook signature, idempotency, 중복/역순 이벤트, 실패·취소·환불·해지 및 entitlement revoke, 결제 로그 민감정보 마스킹, 장애 재조정 job; 통합 보안 테스트.

**최소 산출물:** server/billing/*, tests/billing/*, docs/BILLING_RUNBOOK.md. 반드시 구현 및 테스트의 변경 파일 경로를 명시하고 `docs/implementation/T39_REPORT.md`를 남겨라.

**합격 판정기준:** 중복 webhook도 요금/권한 중복 없음, 결제 성공 확인 없는 권한 부여 금지, 취소 후 권한 회수 정책 일관.

**특별 안전조건:** 실결제는 서면 승인·사업자 설정 완료 후.

실행 순서는 (1) 현 상태 확인 및 작은 실행계획 (2) 최소 변경 구현 (3) 명시한 판정기준의 테스트 작성·실행 (4) 반례·엣지케이스 검토 (5) 변경 파일/테스트 증빙 정리 (6) `PASS/CONDITIONAL/FAIL/BLOCKED` 판정이다. 실행하지 못한 명령은 `NOT_RUN`으로 남기고, 무단 결제/외부 공개/배포/원격 푸시 없이 종료하라. 범위 밖 발견사항은 다음 티켓 후보로 적어라.

**답변 형식:** `판정 → 실제 변경 파일 → 구현 핵심 → 실행한 테스트(명령·결과) → 미검증·잔여 위험 → 다음 티켓 진행 가능 여부`.
