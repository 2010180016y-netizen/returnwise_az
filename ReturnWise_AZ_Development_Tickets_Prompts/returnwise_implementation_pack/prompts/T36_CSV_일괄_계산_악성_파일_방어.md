# T36 | CSV 일괄 계산·악성 파일 방어

> G6 / **조건부 실행: T32의 G5 PASS와 사용자 별도 승인 후에만 실시.**
> 선행 조건: T35,T10

## 개발 에이전트에게 붙여넣을 실행 프롬프트

너는 ReturnWise 프로젝트의 구현 책임자다. 먼저 저장소 상태와 `prompts/00_MASTER_PROMPT.md`, `START_HERE.md`, PRD/금융 산식/법률 게이트/기술 명세를 읽고 현재 티켓의 선행 조건 `T35,T10` 완료 여부를 **실제 파일과 테스트로** 확인하라. 선행 조건 미충족이면 임의 보완·월권하지 말고 BLOCKED 보고서를 작성하라.

**현재 실행할 티켓은 T36 — CSV 일괄 계산·악성 파일 방어 하나뿐이다.**

**목적:** 유료 반복 작업을 빠르게 하되 개인정보/파일 위험을 통제한다.

**구체적 작업 지시:** CSV 템플릿/매핑/미리보기/열별 에러, 파일 크기·행수 제한, CSV injection 방어(내보내기 시 수식 접두어 안전 처리), 인코딩 한글 처리, 입력 PII 경고·차단, 계산은 서버 검증, 비용과 동시성 제한, 진행 취소.

**최소 산출물:** src/features/batch/*, server/batch/*, tests/batch/*. 반드시 구현 및 테스트의 변경 파일 경로를 명시하고 `docs/implementation/T36_REPORT.md`를 남겨라.

**합격 판정기준:** 정상 100/1000행 결과 정확; 악성 formula/큰 파일/인코딩/열 누락 보호; 고객 PII 업로드 경고.

**특별 안전조건:** 반품 주문 원본 CSV의 개인정보를 무심코 저장하지 않게 설계.

실행 순서는 (1) 현 상태 확인 및 작은 실행계획 (2) 최소 변경 구현 (3) 명시한 판정기준의 테스트 작성·실행 (4) 반례·엣지케이스 검토 (5) 변경 파일/테스트 증빙 정리 (6) `PASS/CONDITIONAL/FAIL/BLOCKED` 판정이다. 실행하지 못한 명령은 `NOT_RUN`으로 남기고, 무단 결제/외부 공개/배포/원격 푸시 없이 종료하라. 범위 밖 발견사항은 다음 티켓 후보로 적어라.

**답변 형식:** `판정 → 실제 변경 파일 → 구현 핵심 → 실행한 테스트(명령·결과) → 미검증·잔여 위험 → 다음 티켓 진행 가능 여부`.
