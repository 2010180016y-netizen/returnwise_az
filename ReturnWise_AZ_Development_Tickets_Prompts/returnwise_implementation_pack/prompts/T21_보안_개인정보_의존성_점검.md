# T21 | 보안·개인정보·의존성 점검

> G3 / 무료 MVP 또는 사업검증 단계
> 선행 조건: T19

## 개발 에이전트에게 붙여넣을 실행 프롬프트

너는 ReturnWise 프로젝트의 구현 책임자다. 먼저 저장소 상태와 `prompts/00_MASTER_PROMPT.md`, `START_HERE.md`, PRD/금융 산식/법률 게이트/기술 명세를 읽고 현재 티켓의 선행 조건 `T19` 완료 여부를 **실제 파일과 테스트로** 확인하라. 선행 조건 미충족이면 임의 보완·월권하지 말고 BLOCKED 보고서를 작성하라.

**현재 실행할 티켓은 T21 — 보안·개인정보·의존성 점검 하나뿐이다.**

**목적:** 금전정보 및 사용자의 브라우저 환경을 안전하게 보호한다.

**구체적 작업 지시:** dependency audit, XSS/출력 인코딩, CSP/HTTP response header, 외부 script 없음 점검; source map/stack trace 정책; localStorage 최소저장, PII 필드 없음, network inspector 및 로그 노출 점검; 비밀정보 탐지; 개인정보/쿠키 정책 문구 대조.

**최소 산출물:** docs/SECURITY_AUDIT.md, public/_headers, tests/e2e/privacy.spec.ts. 반드시 구현 및 테스트의 변경 파일 경로를 명시하고 `docs/implementation/T21_REPORT.md`를 남겨라.

**합격 판정기준:** High/Critical 알려진 취약점 0(해결 불가 시 FAIL), 입력값 외부 전송 0, 콘솔/로그 민감정보 0, CSP 충돌 없음.

**특별 안전조건:** 민감값을 포함한 서드파티 analytics 자동 도입 금지.

실행 순서는 (1) 현 상태 확인 및 작은 실행계획 (2) 최소 변경 구현 (3) 명시한 판정기준의 테스트 작성·실행 (4) 반례·엣지케이스 검토 (5) 변경 파일/테스트 증빙 정리 (6) `PASS/CONDITIONAL/FAIL/BLOCKED` 판정이다. 실행하지 못한 명령은 `NOT_RUN`으로 남기고, 무단 결제/외부 공개/배포/원격 푸시 없이 종료하라. 범위 밖 발견사항은 다음 티켓 후보로 적어라.

**답변 형식:** `판정 → 실제 변경 파일 → 구현 핵심 → 실행한 테스트(명령·결과) → 미검증·잔여 위험 → 다음 티켓 진행 가능 여부`.
