# T33 | Pro 기능·법적 범위·아키텍처 재설계

> G6 / **조건부 실행: T32의 G5 PASS와 사용자 별도 승인 후에만 실시.**
> 선행 조건: T32(G5 PASS)

## 개발 에이전트에게 붙여넣을 실행 프롬프트

너는 ReturnWise 프로젝트의 구현 책임자다. 먼저 저장소 상태와 `prompts/00_MASTER_PROMPT.md`, `START_HERE.md`, PRD/금융 산식/법률 게이트/기술 명세를 읽고 현재 티켓의 선행 조건 `T32(G5 PASS)` 완료 여부를 **실제 파일과 테스트로** 확인하라. 선행 조건 미충족이면 임의 보완·월권하지 말고 BLOCKED 보고서를 작성하라.

**현재 실행할 티켓은 T33 — Pro 기능·법적 범위·아키텍처 재설계 하나뿐이다.**

**목적:** 사업 가치가 입증된 기능만 서버 제품으로 확장한다.

**구체적 작업 지시:** 사용자 피드백으로 유료 기능 PRD, 데이터모델, 보존·삭제, 보안/이용약관/개인정보 고지, PG 계약·유지비, 관리자 책임, 새 ADR; MVP 기능 무중단 유지; Pro 개발 기획서를 작성 후 별도 승인.

**최소 산출물:** docs/PRO_PRD.md, docs/ADR/0003-pro-stack.md. 반드시 구현 및 테스트의 변경 파일 경로를 명시하고 `docs/implementation/T33_REPORT.md`를 남겨라.

**합격 판정기준:** G5 PASS 증거와 승인 없으면 BLOCKED; 예산/운영 위험·법률 항목에 승인자 연결.

**특별 안전조건:** 특정 DB/Auth/PG 도구를 근거 없이 채택하지 말 것.

실행 순서는 (1) 현 상태 확인 및 작은 실행계획 (2) 최소 변경 구현 (3) 명시한 판정기준의 테스트 작성·실행 (4) 반례·엣지케이스 검토 (5) 변경 파일/테스트 증빙 정리 (6) `PASS/CONDITIONAL/FAIL/BLOCKED` 판정이다. 실행하지 못한 명령은 `NOT_RUN`으로 남기고, 무단 결제/외부 공개/배포/원격 푸시 없이 종료하라. 범위 밖 발견사항은 다음 티켓 후보로 적어라.

**답변 형식:** `판정 → 실제 변경 파일 → 구현 핵심 → 실행한 테스트(명령·결과) → 미검증·잔여 위험 → 다음 티켓 진행 가능 여부`.
