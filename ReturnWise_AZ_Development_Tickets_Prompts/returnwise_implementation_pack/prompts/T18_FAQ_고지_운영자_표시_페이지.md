# T18 | FAQ·고지·운영자 표시 페이지

> G2 / 무료 MVP 또는 사업검증 단계
> 선행 조건: T12,T02

## 개발 에이전트에게 붙여넣을 실행 프롬프트

너는 ReturnWise 프로젝트의 구현 책임자다. 먼저 저장소 상태와 `prompts/00_MASTER_PROMPT.md`, `START_HERE.md`, PRD/금융 산식/법률 게이트/기술 명세를 읽고 현재 티켓의 선행 조건 `T12,T02` 완료 여부를 **실제 파일과 테스트로** 확인하라. 선행 조건 미충족이면 임의 보완·월권하지 말고 BLOCKED 보고서를 작성하라.

**현재 실행할 티켓은 T18 — FAQ·고지·운영자 표시 페이지 하나뿐이다.**

**목적:** 사용자가 제품 한계와 비용 부담 조건을 이해한다.

**구체적 작업 지시:** FAQ 최소 8개, 계산기 사용방법, 약관 초안, 개인정보 미수집 설명, 법률 비자문 고지, 문의 채널 placeholder; 법적 허용 판단은 사용자 확인 필요; 운영자 상호/연락처는 실정보 없는 경우 임의 게시 금지; 사실 관계 미확인 문구는 REVIEW_REQUIRED 라벨.

**최소 산출물:** src/content/faq.ts, src/content/disclosures.ts, docs/PUBLIC_COPY_REVIEW.md. 반드시 구현 및 테스트의 변경 파일 경로를 명시하고 `docs/implementation/T18_REPORT.md`를 남겨라.

**합격 판정기준:** FAQ 링크/푸터 정상, 미검토 내용을 확정 문구로 배포 못하도록 콘텐츠 승인 필드.

**특별 안전조건:** 사업자 표시·개인정보 처리방침은 실제 운영 형태에 맞춰 사람 승인.

실행 순서는 (1) 현 상태 확인 및 작은 실행계획 (2) 최소 변경 구현 (3) 명시한 판정기준의 테스트 작성·실행 (4) 반례·엣지케이스 검토 (5) 변경 파일/테스트 증빙 정리 (6) `PASS/CONDITIONAL/FAIL/BLOCKED` 판정이다. 실행하지 못한 명령은 `NOT_RUN`으로 남기고, 무단 결제/외부 공개/배포/원격 푸시 없이 종료하라. 범위 밖 발견사항은 다음 티켓 후보로 적어라.

**답변 형식:** `판정 → 실제 변경 파일 → 구현 핵심 → 실행한 테스트(명령·결과) → 미검증·잔여 위험 → 다음 티켓 진행 가능 여부`.
