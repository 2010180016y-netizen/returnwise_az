# T14 | 비용 결과 표·비교 시각화

> G2 / 무료 MVP 또는 사업검증 단계
> 선행 조건: T13,T09

## 개발 에이전트에게 붙여넣을 실행 프롬프트

너는 ReturnWise 프로젝트의 구현 책임자다. 먼저 저장소 상태와 `prompts/00_MASTER_PROMPT.md`, `START_HERE.md`, PRD/금융 산식/법률 게이트/기술 명세를 읽고 현재 티켓의 선행 조건 `T13,T09` 완료 여부를 **실제 파일과 테스트로** 확인하라. 선행 조건 미충족이면 임의 보완·월권하지 말고 BLOCKED 보고서를 작성하라.

**현재 실행할 티켓은 T14 — 비용 결과 표·비교 시각화 하나뿐이다.**

**목적:** 두 지표와 자격 상태를 투명하게 보여준다.

**구체적 작업 지시:** cash/economic 두 열, 메트릭 선택 탭, 최소 비용 강조(eligible >=2), 금액 차이, 순경제적 비용 음수 해석, `확인 필요` 라벨, 이외 옵션은 순위 제외; 수치 기반 막대 및 표 병행.

**최소 산출물:** src/features/calculator/ResultView.tsx, tests/integration/ResultView.test.tsx. 반드시 구현 및 테스트의 변경 파일 경로를 명시하고 `docs/implementation/T14_REPORT.md`를 남겨라.

**합격 판정기준:** 가상 예시 34500/25500 vs 30000/30000 동시 표시; 비허용 부분환불에 추천 배지 없음; 모바일 가로 스크롤 없음.

**특별 안전조건:** `수익/확정절감` 오인 문구 금지.

실행 순서는 (1) 현 상태 확인 및 작은 실행계획 (2) 최소 변경 구현 (3) 명시한 판정기준의 테스트 작성·실행 (4) 반례·엣지케이스 검토 (5) 변경 파일/테스트 증빙 정리 (6) `PASS/CONDITIONAL/FAIL/BLOCKED` 판정이다. 실행하지 못한 명령은 `NOT_RUN`으로 남기고, 무단 결제/외부 공개/배포/원격 푸시 없이 종료하라. 범위 밖 발견사항은 다음 티켓 후보로 적어라.

**답변 형식:** `판정 → 실제 변경 파일 → 구현 핵심 → 실행한 테스트(명령·결과) → 미검증·잔여 위험 → 다음 티켓 진행 가능 여부`.
