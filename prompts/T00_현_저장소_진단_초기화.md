# T00 | 현 저장소 진단·초기화

> G0 / 무료 MVP 또는 사업검증 단계
> 선행 조건: 없음

## 개발 에이전트에게 붙여넣을 실행 프롬프트

너는 ReturnWise 프로젝트의 구현 책임자다. 먼저 저장소 상태와 `prompts/00_MASTER_PROMPT.md`, `START_HERE.md`, PRD/금융 산식/법률 게이트/기술 명세를 읽고 현재 티켓의 선행 조건 `없음` 완료 여부를 **실제 파일과 테스트로** 확인하라. 선행 조건 미충족이면 임의 보완·월권하지 말고 BLOCKED 보고서를 작성하라.

**현재 실행할 티켓은 T00 — 현 저장소 진단·초기화 하나뿐이다.**

**목적:** 작업 환경과 현재 코드/문서를 파악해 안전한 시작점을 만든다.

**구체적 작업 지시:** 기존 repo가 있으면 `git status`, package.json, lockfile, 테스트·CI·호스팅 설정을 읽는다; 없으면 새 디렉터리와 private repo 사용 지침을 작성한다; Node/npm 버전을 확인하고 재현 가능한 실행 명령을 기록한다; 문서 패키지 원본을 `docs/` 및 `prompts/`로 복사하되 충돌 시 보존한다.

**최소 산출물:** docs/implementation/T00_REPORT.md, docs/implementation/ENVIRONMENT.md. 반드시 구현 및 테스트의 변경 파일 경로를 명시하고 `docs/implementation/T00_REPORT.md`를 남겨라.

**합격 판정기준:** 기존 변경사항이 손상되지 않음; 환경 확인/미확인 기록; 작업 가능한 파일목록과 최초 위험/차단 5개 이내.

**특별 안전조건:** 승인 없이 삭제/강제 초기화/원격 push 금지.

실행 순서는 (1) 현 상태 확인 및 작은 실행계획 (2) 최소 변경 구현 (3) 명시한 판정기준의 테스트 작성·실행 (4) 반례·엣지케이스 검토 (5) 변경 파일/테스트 증빙 정리 (6) `PASS/CONDITIONAL/FAIL/BLOCKED` 판정이다. 실행하지 못한 명령은 `NOT_RUN`으로 남기고, 무단 결제/외부 공개/배포/원격 푸시 없이 종료하라. 범위 밖 발견사항은 다음 티켓 후보로 적어라.

**답변 형식:** `판정 → 실제 변경 파일 → 구현 핵심 → 실행한 테스트(명령·결과) → 미검증·잔여 위험 → 다음 티켓 진행 가능 여부`.
