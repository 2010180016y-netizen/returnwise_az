# T26 | 운영자 UAT·법률 문구 수동 승인

> G4 / 무료 MVP 또는 사업검증 단계
> 선행 조건: T25,T18

## 개발 에이전트에게 붙여넣을 실행 프롬프트

너는 ReturnWise 프로젝트의 구현 책임자다. 먼저 저장소 상태와 `prompts/00_MASTER_PROMPT.md`, `START_HERE.md`, PRD/금융 산식/법률 게이트/기술 명세를 읽고 현재 티켓의 선행 조건 `T25,T18` 완료 여부를 **실제 파일과 테스트로** 확인하라. 선행 조건 미충족이면 임의 보완·월권하지 말고 BLOCKED 보고서를 작성하라.

**현재 실행할 티켓은 T26 — 운영자 UAT·법률 문구 수동 승인 하나뿐이다.**

**목적:** 기술적 정확성과 외부 공개 위험을 사람이 확인한다.

**구체적 작업 지시:** 최종 10개 사용자 시나리오 UAT 체크리스트; 법률·플랫폼 출처/문구/운영자표시/개인정보 고지 확인; 상품 특례 검토; 실제 사용자 3~5명 usability test 요청; 스크린샷과 blocker; 사람 서명 칸 포함한 launch dossier.

**최소 산출물:** docs/LAUNCH_APPROVAL.md, docs/UAT_REPORT.md. 반드시 구현 및 테스트의 변경 파일 경로를 명시하고 `docs/implementation/T26_REPORT.md`를 남겨라.

**합격 판정기준:** UAT 결함 P0=0, 법률/게시문구 검토 체크서명; 미완료면 NOT_APPROVED.

**특별 안전조건:** AI가 사용자의 승인·법률 전문가 의견을 대리 서명 금지.

실행 순서는 (1) 현 상태 확인 및 작은 실행계획 (2) 최소 변경 구현 (3) 명시한 판정기준의 테스트 작성·실행 (4) 반례·엣지케이스 검토 (5) 변경 파일/테스트 증빙 정리 (6) `PASS/CONDITIONAL/FAIL/BLOCKED` 판정이다. 실행하지 못한 명령은 `NOT_RUN`으로 남기고, 무단 결제/외부 공개/배포/원격 푸시 없이 종료하라. 범위 밖 발견사항은 다음 티켓 후보로 적어라.

**답변 형식:** `판정 → 실제 변경 파일 → 구현 핵심 → 실행한 테스트(명령·결과) → 미검증·잔여 위험 → 다음 티켓 진행 가능 여부`.
