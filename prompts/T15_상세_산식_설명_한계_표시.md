# T15 | 상세 산식·설명·한계 표시

> G2 / 무료 MVP 또는 사업검증 단계
> 선행 조건: T14

## 개발 에이전트에게 붙여넣을 실행 프롬프트

너는 ReturnWise 프로젝트의 구현 책임자다. 먼저 저장소 상태와 `prompts/00_MASTER_PROMPT.md`, `START_HERE.md`, PRD/금융 산식/법률 게이트/기술 명세를 읽고 현재 티켓의 선행 조건 `T14` 완료 여부를 **실제 파일과 테스트로** 확인하라. 선행 조건 미충족이면 임의 보완·월권하지 말고 BLOCKED 보고서를 작성하라.

**현재 실행할 티켓은 T15 — 상세 산식·설명·한계 표시 하나뿐이다.**

**목적:** 사용자가 계산을 검증·재현하도록 한다.

**구체적 작업 지시:** 방식별 항목 수식 unfold; cash vs economic 정의; 순회수가치 평가 기준, 플랫폼 수수료 환급 확인, 원상품 공통원가 제외 설명; 규정 확인 경고/출처 링크; 산식 복사 텍스트 구성.

**최소 산출물:** src/features/calculator/Breakdown.tsx, src/content/glossary.ts. 반드시 구현 및 테스트의 변경 파일 경로를 명시하고 `docs/implementation/T15_REPORT.md`를 남겨라.

**합격 판정기준:** 모든 결과에 breakdown 존재, 세부 합계=상단 숫자, 설명 누락/불일치 없음.

**특별 안전조건:** 회수가치를 매출로 설명하거나 순이익으로 표현 금지.

실행 순서는 (1) 현 상태 확인 및 작은 실행계획 (2) 최소 변경 구현 (3) 명시한 판정기준의 테스트 작성·실행 (4) 반례·엣지케이스 검토 (5) 변경 파일/테스트 증빙 정리 (6) `PASS/CONDITIONAL/FAIL/BLOCKED` 판정이다. 실행하지 못한 명령은 `NOT_RUN`으로 남기고, 무단 결제/외부 공개/배포/원격 푸시 없이 종료하라. 범위 밖 발견사항은 다음 티켓 후보로 적어라.

**답변 형식:** `판정 → 실제 변경 파일 → 구현 핵심 → 실행한 테스트(명령·결과) → 미검증·잔여 위험 → 다음 티켓 진행 가능 여부`.
