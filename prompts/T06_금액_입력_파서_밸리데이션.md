# T06 | 금액 입력 파서·밸리데이션

> G1 / 무료 MVP 또는 사업검증 단계
> 선행 조건: T05,T03

## 개발 에이전트에게 붙여넣을 실행 프롬프트

너는 ReturnWise 프로젝트의 구현 책임자다. 먼저 저장소 상태와 `prompts/00_MASTER_PROMPT.md`, `START_HERE.md`, PRD/금융 산식/법률 게이트/기술 명세를 읽고 현재 티켓의 선행 조건 `T05,T03` 완료 여부를 **실제 파일과 테스트로** 확인하라. 선행 조건 미충족이면 임의 보완·월권하지 말고 BLOCKED 보고서를 작성하라.

**현재 실행할 티켓은 T06 — 금액 입력 파서·밸리데이션 하나뿐이다.**

**목적:** KRW 정수 및 미입력·경계 오류를 공통 처리한다.

**구체적 작업 지시:** MoneyKRW 타입/parseMoney 함수/입력 에러 타입; 공백·쉼표 정규화; 문자·음수·소수·NaN·무한대·상한초과 방지; required와 optional의 0 허용 분리; 에러 키를 UI 메시지에 연결; 관련 순수 테스트 구현.

**최소 산출물:** src/domain/money.ts, src/domain/validation.ts, tests/unit/money.test.ts. 반드시 구현 및 테스트의 변경 파일 경로를 명시하고 `docs/implementation/T06_REPORT.md`를 남겨라.

**합격 판정기준:** 비정상 입력 20개 이상 테스트; 0과 empty 구분; 숫자 변환 암묵적 강제 없음.

**특별 안전조건:** `Number(value)||0` 같은 유효성 파괴 패턴 금지.

실행 순서는 (1) 현 상태 확인 및 작은 실행계획 (2) 최소 변경 구현 (3) 명시한 판정기준의 테스트 작성·실행 (4) 반례·엣지케이스 검토 (5) 변경 파일/테스트 증빙 정리 (6) `PASS/CONDITIONAL/FAIL/BLOCKED` 판정이다. 실행하지 못한 명령은 `NOT_RUN`으로 남기고, 무단 결제/외부 공개/배포/원격 푸시 없이 종료하라. 범위 밖 발견사항은 다음 티켓 후보로 적어라.

**답변 형식:** `판정 → 실제 변경 파일 → 구현 핵심 → 실행한 테스트(명령·결과) → 미검증·잔여 위험 → 다음 티켓 진행 가능 여부`.
