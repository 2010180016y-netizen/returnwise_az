# T03 | 비용산식·경계값 명세 고정

> G0 / 무료 MVP 또는 사업검증 단계
> 선행 조건: T01,T02

## 개발 에이전트에게 붙여넣을 실행 프롬프트

너는 ReturnWise 프로젝트의 구현 책임자다. 먼저 저장소 상태와 `prompts/00_MASTER_PROMPT.md`, `START_HERE.md`, PRD/금융 산식/법률 게이트/기술 명세를 읽고 현재 티켓의 선행 조건 `T01,T02` 완료 여부를 **실제 파일과 테스트로** 확인하라. 선행 조건 미충족이면 임의 보완·월권하지 말고 BLOCKED 보고서를 작성하라.

**현재 실행할 티켓은 T03 — 비용산식·경계값 명세 고정 하나뿐이다.**

**목적:** 현금과 경제적 비용을 혼동하지 않는 계산 규격을 확정한다.

**구체적 작업 지시:** 02_FINANCIAL_DOMAIN을 소스 오브 트루스로 읽고 모든 비용 유형·현금/비현금 차이·회수 순가치·확정 수수료 크레딧과 제외 공통원가를 표준화; 대안별 대수식 정리; KRW 정수/미입력/금액범위/음수 처리 정의; 비교 가능한 대안 그룹 및 근거없는 추천 금지 선언; C01–C18 수작업 기대값 리뷰.

**최소 산출물:** docs/CALCULATION_CONTRACT.md, tests/fixtures/scenarios.json 초안. 반드시 구현 및 테스트의 변경 파일 경로를 명시하고 `docs/implementation/T03_REPORT.md`를 남겨라.

**합격 판정기준:** 예시 C01 cash=34500 economic=25500; C02 cash=economic=30000; 교환 C15 cash=19500 economic=10500; 경계조건 명세 있음.

**특별 안전조건:** 순회수가치를 원판매가나 매입원가로 자동 대체 금지.

실행 순서는 (1) 현 상태 확인 및 작은 실행계획 (2) 최소 변경 구현 (3) 명시한 판정기준의 테스트 작성·실행 (4) 반례·엣지케이스 검토 (5) 변경 파일/테스트 증빙 정리 (6) `PASS/CONDITIONAL/FAIL/BLOCKED` 판정이다. 실행하지 못한 명령은 `NOT_RUN`으로 남기고, 무단 결제/외부 공개/배포/원격 푸시 없이 종료하라. 범위 밖 발견사항은 다음 티켓 후보로 적어라.

**답변 형식:** `판정 → 실제 변경 파일 → 구현 핵심 → 실행한 테스트(명령·결과) → 미검증·잔여 위험 → 다음 티켓 진행 가능 여부`.
