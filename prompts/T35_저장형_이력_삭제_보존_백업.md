# T35 | 저장형 이력·삭제·보존·백업

> G6 / **조건부 실행: T32의 G5 PASS와 사용자 별도 승인 후에만 실시.**
> 선행 조건: T34

## 개발 에이전트에게 붙여넣을 실행 프롬프트

너는 ReturnWise 프로젝트의 구현 책임자다. 먼저 저장소 상태와 `prompts/00_MASTER_PROMPT.md`, `START_HERE.md`, PRD/금융 산식/법률 게이트/기술 명세를 읽고 현재 티켓의 선행 조건 `T34` 완료 여부를 **실제 파일과 테스트로** 확인하라. 선행 조건 미충족이면 임의 보완·월권하지 말고 BLOCKED 보고서를 작성하라.

**현재 실행할 티켓은 T35 — 저장형 이력·삭제·보존·백업 하나뿐이다.**

**목적:** 월간 분석에 필요한 최소 업무 데이터를 안정적으로 관리한다.

**구체적 작업 지시:** 안전한 데이터 스키마: 회사 내부 caseId(SKU/개인정보 없는 내부 임의키), 금액, 정책확인 상태, 기간; DB migration/rollback; 멱등 처리/보존기간/삭제·내보내기/백업 복구 연습; 장애시 무결성.

**최소 산출물:** db/migrations/*, server/cases/*, docs/DATA_LIFECYCLE.md. 반드시 구현 및 테스트의 변경 파일 경로를 명시하고 `docs/implementation/T35_REPORT.md`를 남겨라.

**합격 판정기준:** 삭제 후 재조회 불가, 백업 복원 점검, 테넌트 분리 테스트, DB migration 롤백.

**특별 안전조건:** 고객 이름·주소·주문번호 강제 수집 금지.

실행 순서는 (1) 현 상태 확인 및 작은 실행계획 (2) 최소 변경 구현 (3) 명시한 판정기준의 테스트 작성·실행 (4) 반례·엣지케이스 검토 (5) 변경 파일/테스트 증빙 정리 (6) `PASS/CONDITIONAL/FAIL/BLOCKED` 판정이다. 실행하지 못한 명령은 `NOT_RUN`으로 남기고, 무단 결제/외부 공개/배포/원격 푸시 없이 종료하라. 범위 밖 발견사항은 다음 티켓 후보로 적어라.

**답변 형식:** `판정 → 실제 변경 파일 → 구현 핵심 → 실행한 테스트(명령·결과) → 미검증·잔여 위험 → 다음 티켓 진행 가능 여부`.
