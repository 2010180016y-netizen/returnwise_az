# T17 | 복사·초기화·예시·비정상 복구

> G2 / 무료 MVP 또는 사업검증 단계
> 선행 조건: T14,T16

## 개발 에이전트에게 붙여넣을 실행 프롬프트

너는 ReturnWise 프로젝트의 구현 책임자다. 먼저 저장소 상태와 `prompts/00_MASTER_PROMPT.md`, `START_HERE.md`, PRD/금융 산식/법률 게이트/기술 명세를 읽고 현재 티켓의 선행 조건 `T14,T16` 완료 여부를 **실제 파일과 테스트로** 확인하라. 선행 조건 미충족이면 임의 보완·월권하지 말고 BLOCKED 보고서를 작성하라.

**현재 실행할 티켓은 T17 — 복사·초기화·예시·비정상 복구 하나뿐이다.**

**목적:** 업무에서 즉시 활용 가능한 보조 기능을 만든다.

**구체적 작업 지시:** 익명 요약 복사(처리대안/두 지표/확인 필요/산식 주요값), Clipboard 실패 fallback; example reset; 입력 전체 reset; error boundary와 안전 메시지; 복사 성공/실패 피드백.

**최소 산출물:** src/lib/clipboard.ts, src/features/calculator/Actions.tsx, tests/integration/actions.test.tsx. 반드시 구현 및 테스트의 변경 파일 경로를 명시하고 `docs/implementation/T17_REPORT.md`를 남겨라.

**합격 판정기준:** copy 성공/권한거절 테스트; URL/쿠키/분석 payload에 계산 값 없음; 초기화 후 계산 값 지워짐.

**특별 안전조건:** 클립보드 결과에 실 구매자 정보 포함 금지.

실행 순서는 (1) 현 상태 확인 및 작은 실행계획 (2) 최소 변경 구현 (3) 명시한 판정기준의 테스트 작성·실행 (4) 반례·엣지케이스 검토 (5) 변경 파일/테스트 증빙 정리 (6) `PASS/CONDITIONAL/FAIL/BLOCKED` 판정이다. 실행하지 못한 명령은 `NOT_RUN`으로 남기고, 무단 결제/외부 공개/배포/원격 푸시 없이 종료하라. 범위 밖 발견사항은 다음 티켓 후보로 적어라.

**답변 형식:** `판정 → 실제 변경 파일 → 구현 핵심 → 실행한 테스트(명령·결과) → 미검증·잔여 위험 → 다음 티켓 진행 가능 여부`.
