# T10 | 계산 회귀·성질 테스트 및 G1 심사

> G1 / 무료 MVP 또는 사업검증 단계
> 선행 조건: T06,T07,T08,T09

## 개발 에이전트에게 붙여넣을 실행 프롬프트

너는 ReturnWise 프로젝트의 구현 책임자다. 먼저 저장소 상태와 `prompts/00_MASTER_PROMPT.md`, `START_HERE.md`, PRD/금융 산식/법률 게이트/기술 명세를 읽고 현재 티켓의 선행 조건 `T06,T07,T08,T09` 완료 여부를 **실제 파일과 테스트로** 확인하라. 선행 조건 미충족이면 임의 보완·월권하지 말고 BLOCKED 보고서를 작성하라.

**현재 실행할 티켓은 T10 — 계산 회귀·성질 테스트 및 G1 심사 하나뿐이다.**

**목적:** 수식과 법적 안전조건을 자동화 테스트로 잠근다.

**구체적 작업 지시:** C01–C18/L01–L08 fixture 기반 테스트, random/property-like 테스트(운송비 증가, 회수가치 증가, 동일 입력 동일 결과), 오류 및 경계; domain 브랜치 커버리지 보고; 티켓 G1 체크리스트 작성.

**최소 산출물:** tests/fixtures/*, docs/implementation/G1_REPORT.md. 반드시 구현 및 테스트의 변경 파일 경로를 명시하고 `docs/implementation/T10_REPORT.md`를 남겨라.

**합격 판정기준:** 18개 계산/8개 게이트 테스트 모두 PASS; domain 브랜치 95% 목표 또는 미달과 잔여위험 명시; 게이트 FAIL이면 UI 개발 차단.

**특별 안전조건:** 스냅샷만으로 금액 정확성 보장 금지.

실행 순서는 (1) 현 상태 확인 및 작은 실행계획 (2) 최소 변경 구현 (3) 명시한 판정기준의 테스트 작성·실행 (4) 반례·엣지케이스 검토 (5) 변경 파일/테스트 증빙 정리 (6) `PASS/CONDITIONAL/FAIL/BLOCKED` 판정이다. 실행하지 못한 명령은 `NOT_RUN`으로 남기고, 무단 결제/외부 공개/배포/원격 푸시 없이 종료하라. 범위 밖 발견사항은 다음 티켓 후보로 적어라.

**답변 형식:** `판정 → 실제 변경 파일 → 구현 핵심 → 실행한 테스트(명령·결과) → 미검증·잔여 위험 → 다음 티켓 진행 가능 여부`.
