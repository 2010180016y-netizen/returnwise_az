# T16 | 선택적 기본값 로컬 저장

> G2 / 무료 MVP 또는 사업검증 단계
> 선행 조건: T13

## 개발 에이전트에게 붙여넣을 실행 프롬프트

너는 ReturnWise 프로젝트의 구현 책임자다. 먼저 저장소 상태와 `prompts/00_MASTER_PROMPT.md`, `START_HERE.md`, PRD/금융 산식/법률 게이트/기술 명세를 읽고 현재 티켓의 선행 조건 `T13` 완료 여부를 **실제 파일과 테스트로** 확인하라. 선행 조건 미충족이면 임의 보완·월권하지 말고 BLOCKED 보고서를 작성하라.

**현재 실행할 티켓은 T16 — 선택적 기본값 로컬 저장 하나뿐이다.**

**목적:** 반복 사용자 편의 확보하면서 데이터 노출을 최소화한다.

**구체적 작업 지시:** 사용자 체크 후 seller-paid 배송비·기본 검수비 같은 비민감 값만 localStorage 저장; schemaVersion + TTL 90일 + 잘못된 값/구버전 마이그레이션; 저장/삭제/이 브라우저만 이용 안내; 브라우저 저장 차단 시 정상 작동.

**최소 산출물:** src/lib/storage.ts, tests/unit/storage.test.ts. 반드시 구현 및 테스트의 변경 파일 경로를 명시하고 `docs/implementation/T16_REPORT.md`를 남겨라.

**합격 판정기준:** 명시 체크 전 저장 0건; 전체 환불액/고객 요청 정보 저장 금지; 초기화 완전 삭제.

**특별 안전조건:** 자동 저장 기본값 OFF.

실행 순서는 (1) 현 상태 확인 및 작은 실행계획 (2) 최소 변경 구현 (3) 명시한 판정기준의 테스트 작성·실행 (4) 반례·엣지케이스 검토 (5) 변경 파일/테스트 증빙 정리 (6) `PASS/CONDITIONAL/FAIL/BLOCKED` 판정이다. 실행하지 못한 명령은 `NOT_RUN`으로 남기고, 무단 결제/외부 공개/배포/원격 푸시 없이 종료하라. 범위 밖 발견사항은 다음 티켓 후보로 적어라.

**답변 형식:** `판정 → 실제 변경 파일 → 구현 핵심 → 실행한 테스트(명령·결과) → 미검증·잔여 위험 → 다음 티켓 진행 가능 여부`.
