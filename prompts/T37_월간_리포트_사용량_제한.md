# T37 | 월간 리포트·사용량 제한

> G6 / **조건부 실행: T32의 G5 PASS와 사용자 별도 승인 후에만 실시.**
> 선행 조건: T35,T36

## 개발 에이전트에게 붙여넣을 실행 프롬프트

너는 ReturnWise 프로젝트의 구현 책임자다. 먼저 저장소 상태와 `prompts/00_MASTER_PROMPT.md`, `START_HERE.md`, PRD/금융 산식/법률 게이트/기술 명세를 읽고 현재 티켓의 선행 조건 `T35,T36` 완료 여부를 **실제 파일과 테스트로** 확인하라. 선행 조건 미충족이면 임의 보완·월권하지 말고 BLOCKED 보고서를 작성하라.

**현재 실행할 티켓은 T37 — 월간 리포트·사용량 제한 하나뿐이다.**

**목적:** Pro 가치인 반복 손실 분석과 요금제 경계를 구현한다.

**구체적 작업 지시:** 월/사유/SKU 범주별 평균 처리비/합계/현금 지출, 비용지표 명시, 사용자별 quota와 server-side guard, 무료와 Pro 플랜 기능 경계, 이력 삭제/익명 export, 환율/세금 혼합 없음.

**최소 산출물:** src/features/reports/*, server/usage/*, tests/reports/*. 반드시 구현 및 테스트의 변경 파일 경로를 명시하고 `docs/implementation/T37_REPORT.md`를 남겨라.

**합격 판정기준:** 집계 fixture가 단건 합계와 일치, 권한/사용량 초과 테스트 PASS, 무료 사용자 Pro 접근 차단.

**특별 안전조건:** Pro 관련 현금수익을 사용자의 실제 수익으로 오인시킬 표현 금지.

실행 순서는 (1) 현 상태 확인 및 작은 실행계획 (2) 최소 변경 구현 (3) 명시한 판정기준의 테스트 작성·실행 (4) 반례·엣지케이스 검토 (5) 변경 파일/테스트 증빙 정리 (6) `PASS/CONDITIONAL/FAIL/BLOCKED` 판정이다. 실행하지 못한 명령은 `NOT_RUN`으로 남기고, 무단 결제/외부 공개/배포/원격 푸시 없이 종료하라. 범위 밖 발견사항은 다음 티켓 후보로 적어라.

**답변 형식:** `판정 → 실제 변경 파일 → 구현 핵심 → 실행한 테스트(명령·결과) → 미검증·잔여 위험 → 다음 티켓 진행 가능 여부`.
