# T29 | 실사용자 인터뷰·사용성 검증

> G5 / 무료 MVP 또는 사업검증 단계
> 선행 조건: T28

## 개발 에이전트에게 붙여넣을 실행 프롬프트

너는 ReturnWise 프로젝트의 구현 책임자다. 먼저 저장소 상태와 `prompts/00_MASTER_PROMPT.md`, `START_HERE.md`, PRD/금융 산식/법률 게이트/기술 명세를 읽고 현재 티켓의 선행 조건 `T28` 완료 여부를 **실제 파일과 테스트로** 확인하라. 선행 조건 미충족이면 임의 보완·월권하지 말고 BLOCKED 보고서를 작성하라.

**현재 실행할 티켓은 T29 — 실사용자 인터뷰·사용성 검증 하나뿐이다.**

**목적:** 재방문 가능성과 업무 적합성을 실제 사람에게 확인한다.

**구체적 작업 지시:** 15~20명 인터뷰 스크립트, 반품 발생 빈도/현재 대안/고통도/시간절감/다시 사용 의사; 실계약·주문 정보 수집 금지; 유효 참여자 기록 양식; 5회 이상 구체적 반복 이용 사례; 정성정보를 문제별로 코딩.

**최소 산출물:** docs/CUSTOMER_DISCOVERY.md, docs/INTERVIEW_LOG_TEMPLATE.csv. 반드시 구현 및 테스트의 변경 파일 경로를 명시하고 `docs/implementation/T29_REPORT.md`를 남겨라.

**합격 판정기준:** 실제 인터뷰가 없으면 INTERVIEW_PENDING; 추정 인터뷰 인용 금지; 개선 우선순위 상위 5개 산출.

**특별 안전조건:** 고객의 실명/연락처 저장은 별도 동의·보호체계 없이 금지.

실행 순서는 (1) 현 상태 확인 및 작은 실행계획 (2) 최소 변경 구현 (3) 명시한 판정기준의 테스트 작성·실행 (4) 반례·엣지케이스 검토 (5) 변경 파일/테스트 증빙 정리 (6) `PASS/CONDITIONAL/FAIL/BLOCKED` 판정이다. 실행하지 못한 명령은 `NOT_RUN`으로 남기고, 무단 결제/외부 공개/배포/원격 푸시 없이 종료하라. 범위 밖 발견사항은 다음 티켓 후보로 적어라.

**답변 형식:** `판정 → 실제 변경 파일 → 구현 핵심 → 실행한 테스트(명령·결과) → 미검증·잔여 위험 → 다음 티켓 진행 가능 여부`.
