# T31 | Pro 가격·지불 의사 실험

> G5 / 무료 MVP 또는 사업검증 단계
> 선행 조건: T29

## 개발 에이전트에게 붙여넣을 실행 프롬프트

너는 ReturnWise 프로젝트의 구현 책임자다. 먼저 저장소 상태와 `prompts/00_MASTER_PROMPT.md`, `START_HERE.md`, PRD/금융 산식/법률 게이트/기술 명세를 읽고 현재 티켓의 선행 조건 `T29` 완료 여부를 **실제 파일과 테스트로** 확인하라. 선행 조건 미충족이면 임의 보완·월권하지 말고 BLOCKED 보고서를 작성하라.

**현재 실행할 티켓은 T31 — Pro 가격·지불 의사 실험 하나뿐이다.**

**목적:** 실제로 돈을 낼 고객이 있는지 개발 전 검증한다.

**구체적 작업 지시:** CSV/저장/월간 리포트 기능 선호 조사; 월 9900/14900/19900원 가격 제시, 실제 결제 없음과 대기 신청의 차이 명시; 카운트와 반대 의견 기록; 예상 PG/지원/유지비와 단위경제 계산; 구매의사 명시적 대상 5명 목표.

**최소 산출물:** docs/PRO_VALIDATION.md, docs/UNIT_ECONOMICS.csv. 반드시 구현 및 테스트의 변경 파일 경로를 명시하고 `docs/implementation/T31_REPORT.md`를 남겨라.

**합격 판정기준:** 기초 증빙 없으면 Pro 착수 차단; 가격 실험은 실제 구독 매출로 오인 금지.

**특별 안전조건:** 대기명단과 매출을 혼동 금지, 무단 광고성 메일 금지.

실행 순서는 (1) 현 상태 확인 및 작은 실행계획 (2) 최소 변경 구현 (3) 명시한 판정기준의 테스트 작성·실행 (4) 반례·엣지케이스 검토 (5) 변경 파일/테스트 증빙 정리 (6) `PASS/CONDITIONAL/FAIL/BLOCKED` 판정이다. 실행하지 못한 명령은 `NOT_RUN`으로 남기고, 무단 결제/외부 공개/배포/원격 푸시 없이 종료하라. 범위 밖 발견사항은 다음 티켓 후보로 적어라.

**답변 형식:** `판정 → 실제 변경 파일 → 구현 핵심 → 실행한 테스트(명령·결과) → 미검증·잔여 위험 → 다음 티켓 진행 가능 여부`.
