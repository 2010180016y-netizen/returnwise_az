# T09 | 대안 비교·순위 로직

> G1 / 무료 MVP 또는 사업검증 단계
> 선행 조건: T07,T08

## 개발 에이전트에게 붙여넣을 실행 프롬프트

너는 ReturnWise 프로젝트의 구현 책임자다. 먼저 저장소 상태와 `prompts/00_MASTER_PROMPT.md`, `START_HERE.md`, PRD/금융 산식/법률 게이트/기술 명세를 읽고 현재 티켓의 선행 조건 `T07,T08` 완료 여부를 **실제 파일과 테스트로** 확인하라. 선행 조건 미충족이면 임의 보완·월권하지 말고 BLOCKED 보고서를 작성하라.

**현재 실행할 티켓은 T09 — 대안 비교·순위 로직 하나뿐이다.**

**목적:** 허용된 동질 대안끼리만 지표를 비교한다.

**구체적 작업 지시:** cash/economic 기준 선택 UI용 selector; default economic이지만 cash 탭 별도; 자격 충족 대안 >=2일 때만 최저 비용 및 차액 표시; 동점 처리; 그룹 내 교환/환불 분리; 대안 차이와 누락 비용 가정 노출; rank에 source confidence 포함.

**최소 산출물:** src/domain/compare.ts, tests/unit/compare.test.ts. 반드시 구현 및 테스트의 변경 파일 경로를 명시하고 `docs/implementation/T09_REPORT.md`를 남겨라.

**합격 판정기준:** eligible 0/1/2개 각각 올바른 UI용 데이터; 미확인 옵션은 rank 제외; 현금과 경제적 지표 섞지 않음.

**특별 안전조건:** 불허 옵션을 회색 카드로 볼 수는 있어도 최저 비용으로 강조 금지.

실행 순서는 (1) 현 상태 확인 및 작은 실행계획 (2) 최소 변경 구현 (3) 명시한 판정기준의 테스트 작성·실행 (4) 반례·엣지케이스 검토 (5) 변경 파일/테스트 증빙 정리 (6) `PASS/CONDITIONAL/FAIL/BLOCKED` 판정이다. 실행하지 못한 명령은 `NOT_RUN`으로 남기고, 무단 결제/외부 공개/배포/원격 푸시 없이 종료하라. 범위 밖 발견사항은 다음 티켓 후보로 적어라.

**답변 형식:** `판정 → 실제 변경 파일 → 구현 핵심 → 실행한 테스트(명령·결과) → 미검증·잔여 위험 → 다음 티켓 진행 가능 여부`.
