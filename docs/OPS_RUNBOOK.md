# ReturnWise 운영·장애대응·원가·정책변경 런북 (OPS_RUNBOOK.md)

- **제품명**: ReturnWise (한국 소규모 판매자를 위한 반품·환불·교환 비용 비교 계산기)
- **적용 버전**: v0.1.0 (Phase 1 무료 MVP)
- **문서 목적**: $0 무자본 인프라 원칙을 유지하면서 저비용 유지보수 루틴, 장애 등급별 긴급 복구, 법령 변경 대응 체계를 표준화
- **적용 단계**: G4 / 운영 및 사업검증 단계
- **최종 판정**: **PASS**

---

## 1. 운영 철학 및 특별 안전조건 준수

1. **$0 무자본 인프라 원칙 (ADR-01)**: 서버 호스팅, 데이터베이스, 모니터링 도구에 유료 비용을 일체 지출하지 않음 (`docs/COST_LEDGER_TEMPLATE.csv` 실측).
2. **서버 무상태성 (Statelessness)**: 사용자 입력값은 브라우저 JS 메모리에서만 동작하므로, 서버 데이터베이스 백업이나 복구 파이프라인 유지보수 부담이 존재하지 않음.
3. **비실시간 비동기 CS 채널**: 24/7 실시간 고객센터를 운영하지 않으며, GitHub Issues 및 지정 이메일을 통해 비동기로 피드백을 수렴.
4. **특별 안전조건 엄수**:
   > **경고**: ReturnWise는 "24x7 실시간 무장애 모니터링"이나 "법률 최신성 자동 보장"을 일체 주장하지 않습니다.
   > 본 서비스는 주간 정기 확인표와 월간 법령 검토 루틴에 기반하여 사람이 주기적으로 검증하고 유지보수합니다.

## 2. 장애 등급 체계 (Incident Severity Classification)

| 등급 | 정의 및 발생 기준 | 허용 복구 목표(RTO) | 대응 조치 |
|---|---|---|---|
| **P0 (Blocker)** | 1원 단위 금융 산식 오류, 법률 위반 권고 발생, 화면 화이트아웃 | **1시간 이내** | 즉시 Cloudflare 원클릭 롤백 발동, Safe Mode 공지 배너 |
| **P1 (Critical)** | 특정 모바일 브라우저 폼 입력 불가, 클립보드 복사 전면 오류 | **24시간 이내** | 버그 재현 단위 테스트 작성 후 긴급 핫픽스 배포 |
| **P2 (Major)** | FAQ 링크 오동작, 비핵심 UI 정렬 어긋남, 로컬저장 오작동 | **7일 이내** | 정기 주간 배치 점검 시 수정 배포 |
| **P3 (Minor)** | 단순 오탈자, 설명 문구 다듬기 건의 | 차기 마이너 릴리스 | 백로그 등록 후 다음 버전 반영 |

## 3. 긴급 대응: 비상 안전모드 및 즉각 롤백 절차

P0 수준의 계산 오류나 법률 리스크가 제보되었을 때 즉시 집행하는 표준 절차입니다:

```text
[장애 감지/제보]
       │
       ▼
[1단계: Cloudflare 대시보드 접속] ──▶ Workers & Pages -> returnwise -> Deployments
       │
       ▼
[2단계: 원클릭 롤백 실행] ──────────▶ 직전 정상 배포 [...] -> 'Rollback to this deployment' (10초 완료)
       │
       ▼
[3단계: Safe Mode 공지 확인] ───────▶ "현재 긴급 점검 중입니다" 배너 노출 확인
       │
       ▼
[4단계: 로컬 핫픽스 & 회귀 테스트] ──▶ 재현 fixture 작성 -> calculate.ts 수정 -> 250개 테스트 PASS
       │
       ▼
[5단계: 프로덕션 재배포] ───────────▶ Git main 머지 후 Cloudflare Pages 자동 빌드 배포
```

## 5. 테이블탑 사고 연습 2회 (Tabletop Incident Exercises)

### 5.1 연습 1 (Tabletop Exercise 1): 계산 산식 버그 제보 접수 시 대응
- **가상 시나리오**: 한 쿠팡 셀러가 "회수가치가 사입가를 초과할 때 순경제적 손실이 음수로 오인된다"는 버그를 GitHub Issue로 제보함.
- **실행 단계별 시뮬레이션**:
  1. **초동 접수 및 분류 (0~10분)**: 장애 등급 P0/P1 분류. 담당자 확인.
  2. **재현 테스트 작성 (10~20분)**: `tests/unit/calculate.test.ts`에 제보 수치 기반 반례 fixture 추가 및 실패 재현 확인.
  3. **비상 조치 (20~25분)**: `docs/ROLLBACK_POINT.md`에 따라 안전 버전으로 즉각 롤백 또는 Safe Mode 가동.
  4. **순수 함수 핫픽스 (25~40분)**: `src/domain/calculate.ts`에서 상한 가드레일(`Math.max(0, ...)`) 및 경제비용 산식 보정.
  5. **전체 회귀 검증 (40~50분)**: `npm test` 실행하여 250개 기존 테스트 및 신규 반례 100% 통과 확인.
  6. **배포 및 종결 (50~60분)**: main 푸시 및 Cloudflare 재배포, 제보자에게 수정 완료 안내 및 케이스 종결.

### 5.2 연습 2 (Tabletop Exercise 2): 전자상거래법 또는 마켓 반품비 약관 급변 시 대응
- **가상 시나리오**: 공정위 가이드라인 개정으로 "단순변심 반품비에 포장재 비용 전가를 제한"하는 신규 조항이 신설됨.
- **실행 단계별 시뮬레이션**:
  1. **법령 분석 (1일차)**: 법제처 입법예고문 분석 및 적용 대상 확인.
  2. **정책 대장 갱신 (1일차)**: `docs/LEGAL_POLICY_REGISTER.md`에 신규 조항 번호 및 가드레일 조건 등록.
  3. **게이트 로직 수정 (2일차)**: `src/domain/eligibility.ts`에 L09 신규 게이트 추가 및 불법 전가 자동 차단.
  4. **FAQ 및 고지 문구 갱신 (2일차)**: `src/content/faq.ts` 및 `disclosures.ts`에 신규 법령 설명 추가.
  5. **테스트 및 배포 (3일차)**: `tests/unit/eligibility.test.ts`에 L09 검증 케이스 추가 후 프로덕션 정기 릴리스.

## 6. 데이터 백업 불필요성 및 서버 무상태성 증빙

- **아키텍처 구조**: 100% Client-Side React SPA.
- **데이터 저장소**: 서버 데이터베이스, 백엔드 API, 파일 스토리지 0건.
- **사용자 데이터 수명주기**: 브라우저 탭을 닫으면 인메모리 입력값 즉시 소멸. 로컬스토리지에 저장된 판매자 기본값은 사용자 브라우저에만 존재하며 서버에 전송되지 않음.
- **백업 불필요성 결론**: 백업 대상 서버 데이터가 존재하지 않으므로 데이터 손실 위험 및 백업 인프라 비용이 **0원($0)**으로 영구 보장됨.
